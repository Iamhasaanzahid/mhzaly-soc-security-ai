The difference

Every claim carries its own proof.

A finding only reaches a report after it survives verification. Then it is committed to a hash chain, which means the report cannot be quietly edited later.

Score & gate

Every candidate is scored 0–100, de-duplicated across runs and filtered by a confidence floor and a severity floor.

Verify

Calibrated probes, real TLS chain validation and content signatures. A 200 OK is never accepted as proof on its own.

Chain

Each verified finding commits to the hash of the record before it. Edit one past record and the whole chain breaks.

Explain

Posture is a rubric, not a vibe: each factor's weight, the finding behind it and the confidence that produced it.

Reports

Written like a consultant. Not a scanner.

The Human Council argues with itself before you ever read the report: a consultant, a red teamer, a blue teamer and a skeptic. Then the assessment is written in plain English.

  • Evidence first, opinions clearly labelled as opinions.
  • A skeptic perspective that challenges the confidence level.
  • Hallucination guard: identifiers not in the evidence are flagged.
  • Client deliverables export as Markdown and PDF.

Questions

Straight answers.

Is this just another vulnerability scanner?

No. It is an operations platform built around the opposite premise: fewer findings, each one verified, each one carrying evidence, and each one explainable in a client report. Subdomains are inventory, not findings.

What does "proof-carrying" actually mean?

Every verified finding is written to an append-only ledger where each record commits to the hash of the record before it. If a past finding is edited, the chain no longer verifies. The proof pack exports the whole chain so an auditor can recompute it independently.

Do I need an LLM API key?

No. The local analyst engine writes a complete report without any network call. An optional Groq key adds model-polished prose, but the findings and the evidence are identical either way.

What can it scan?

Public web surfaces you own or are authorised to test: headers, TLS, cookies, CORS, bounded same-origin crawl, robots/sitemap mining, SPF/DMARC, subdomain enumeration, and CPE-confirmed CVE correlation. Targets resolving to private, loopback, link-local or cloud-metadata addresses are refused by the connector layer.

Is it safe to run against a client?

Only with written authorisation. The console requires an explicit authorisation acknowledgement before a scan, enforces a per-day scan quota, and refuses internal addresses. You remain responsible for scope.

Where does the data live?

In a single SQLite file on the host you run it on. There is no external telemetry. Back it up like any other database, and treat the proof pack as an audit artefact.
